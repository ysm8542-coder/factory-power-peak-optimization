# 공장 전력 수요 예측과 인원 배분 최적화
2021년 공장 전력·생산·기상 데이터(1시간 단위)로 전력 수요를 예측하고 Peak를 최적화하는 프로젝트. 다변량 LSTM으로 다음 1시간 전력을 예측하고, 예측 오차가 큰 조건(고온·고생산·아침 시간대)을 분석해 반영한 보강+보정 LSTM으로 MAE를 8.74에서 6.34로, RMSE를 12.72에서 9.45로 개선했다. 회귀·XGBoost·SHAP으로 전력 Peak 발생 요인을 분석했으며, MILP 최적화로 생산 목표를 지키면서 전력 Peak와 인건비·전기요금을 줄이는 라인 운영 및 일용직 인원 배치안을 도출했다.

1. Dataset_processing.ipynb — 원본 데이터 전처리
--------------------------------------------------------------------------
- 2021년 1월~9월, 1시간 단위 공장 전력 · 생산 · 기상 데이터를 점검하고 정제한다.
- 주요 처리
  · 범위를 벗어난 `시간` 값(7/13, 7/15) 복원 및 datetime 연속성 검증
  · 15분 단위 전력값으로 파생 변수 생성 (전력 구간합계 / 최대값 / 최소값 / 변동폭)
  · 결측치 처리: 풍속 · 강수량은 선형 보간, 공장인원은 RandomForest 회귀로 대체
  · 공휴일(대체공휴일 포함)의 요일 코드를 8로 변경
- 입력: okm_augumented_2021.csv
- 출력: okm_augumented_2021_processed.xlsx


--------------------------------------------------------------------------
2. normal_single_variation_lstm.ipynb — 단변량 LSTM (기준 모델)
--------------------------------------------------------------------------
- 전력 사용량(`평균`) 하나만 입력으로 직전 24시간 → 다음 1시간 전력을 예측한다.
- 다변량 모델과 비교하기 위한 기준선(baseline)이다.
- 학습 85% / 테스트 15%, 평가 지표 RMSE · MAE · R²


--------------------------------------------------------------------------
3. LSTM_AIModel.ipynb / LSTM_AIModel.py — 다변량 LSTM (기본 모델)
--------------------------------------------------------------------------
- 전력 · 생산량 · 기상 · 공장인원 등 13개 변수의 직전 24시간으로 다음 1시간 전력을 예측한다.
- 모델 구조: LSTM(64) → Dropout → LSTM(32) → Dropout → Dense(16) → Dense(1)
- 노트북 (LSTM_AIModel.ipynb)
  · 학습 구간 시나리오 A~D 비교 (2 · 3 · 4개 구간 분할 vs 1~9월 전체)
  · 시나리오 D 확장 윈도우(Expanding Window) 검증
  · 시간대별 · 평일/주말별 성능, 전력 급증(40%↑) 탐지 성능 분석
  · 1~9월 전력 · 운영 지표 리포트
- 모듈 (LSTM_AIModel.py)
  · 노트북의 공통 함수(load_data, make_sequences, train_lstm_model, evaluate_model)와
    설정값(FEATURES, TARGET, WINDOW_SIZE)을 정리한 파일. 다른 노트북에서 import 해서 사용한다.
  · 직접 실행하면 시나리오 A~D 성능 비교 결과를 출력한다.


--------------------------------------------------------------------------
4. Make_full_power_pkl.ipynb — 예측 결과 · 오차 데이터셋 생성
--------------------------------------------------------------------------
- LSTM_AIModel.py의 모델(시나리오 D)로 1~9월 전체를 예측하고 실제값 · 예측값 · 오차 · 오차율 ·
  과대/과소 여부 · 입력 조건을 한 표로 저장한다. (오차 원인 분석의 입력)
- 기상 4개 변수(기온 · 습도 · 강수량 · 풍속)를 동시에 예측하는 다중 출력 LSTM도 포함한다.
- 출력: full_df_power_only.pkl / .xlsx, weather_prediction_5cols.xlsx


--------------------------------------------------------------------------
5. Error_Driver_Pipeline.ipynb — 예측 오차 원인 분석
--------------------------------------------------------------------------
- 예측 오차를 허용(±10%) / 중간 / 큰 × 과소 / 과대 그룹으로 나누고, 어떤 조건에서 큰 오차가 나는지 분석한다.
- 분석 방법
  · 시각별 · 변수 구간별 오차 비율
  · 시각 · 근무유형을 통제한 변수 비교 (표준화 차이)
  · 주 단위 블록 교차검증 분류 모델 + permutation 기반 요인별 영향력
- 주요 결과: 생산량 · 인원이 많을 때, 28℃ 이상 고온일 때, 아침 07~11시에 큰 과소예측이 많다.
- 입력: full_df_power_only.pkl
- 출력: Error_Driver_Pipeline_결과.xlsx


--------------------------------------------------------------------------
6. LSTM_AIModel_Enhanced.py — 보강 + 보정 LSTM (개선 모델)
--------------------------------------------------------------------------
- 오차 원인 분석 결과를 반영한 2단계 전력 예측 모델 모듈.
  · 1단계 보강 LSTM: 기존 입력 + 오차 원인 변수(시간대 · 평소/최근 부하 패턴 · 생산/인원 변화 ·
    고온 · 누적 고온 · 다음 시간 계획/예보 값) + peak 가중 학습
  · 2단계 잔차 보정: out-of-fold 잔차로 학습한 GBM 2개(peak 보정형 · 스태킹형) 앙상블
- 8:2 분할(split_82)과 확장 윈도우(expanding_window) 검증, 평가 지표 함수(metrics, peak_metrics)를 제공한다.


--------------------------------------------------------------------------
7. LSTM_Enhanced_Performance.ipynb — 개선 모델 성능 리포트
--------------------------------------------------------------------------
- 일반 LSTM / 보강 LSTM / 보강+보정 모델을 같은 조건에서 학습해 성능을 비교한다.
- 확장 윈도우 기준 MAE 8.74 → 6.34, RMSE 12.72 → 9.45 (일반 LSTM → 보강+보정)
- 시간대별 · 평일/주말별 성능, 7월 고온기 peak 분석, 오차 원인 조건별 개선율, 급증 탐지 성능
- 첫 실행 시 학습 결과를 enhanced_results.pkl에 저장하고 이후에는 불러와서 사용한다 (CPU 기준 약 50분).
- 출력: enhanced_results.pkl, 보강보정모델_성능리포트.xlsx

--------------------------------------------------------------------------
7-1. LSTM_Enhanced_Performance.ipynb — 상세 설명 (7번 보충)
--------------------------------------------------------------------------
- 역할: 오차 원인 분석(5번)을 반영한 보강 + 보정 LSTM이 일반 LSTM보다 얼마나 잘 맞히는지,
  어디서 특히 좋아지는지를 수치와 그래프로 보여 주는 성능 리포트. 모델 코드는
  LSTM_AIModel_Enhanced.py(6번)에 있고, 이 노트북은 학습 · 검증을 실행하고 결과를 정리한다.
- 비교하는 세 모델 (같은 조건에서 학습)
  · 일반 LSTM        기존 13개 입력, LSTM(64) → LSTM(32) → Dense(16) → Dense(1)
  · 보강 LSTM        같은 구조 + 오차 원인 변수 36개(총 49개 입력) + peak 가중 학습  (1단계 중간 결과)
  · 보강 + 보정      보강 LSTM + 잔차 보정(GBM 2개 앙상블)  ← 최종 모델
  보강 LSTM은 peak 가중 학습 때문에 단독으로는 저부하 시간에 과대예측이 생길 수 있고,
  2단계 잔차 보정이 이를 바로잡는다.
- 검증 방식
  · 8:2 분할     시간 순서로 앞 80% 학습, 뒤 20% 테스트 (1,234시간, 7/25 ~ 9/14)
  · 확장 윈도우  초기 50% 학습 후 4개 fold를 순서대로 테스트 (3,084시간, LSTM_AIModel 시나리오 D와 동일)
- 노트북 구성
  · 0절  라이브러리 · 데이터 · 학습 (또는 저장된 결과 불러오기)
  · 1절  수치 성능: 8:2 분할, 확장 윈도우(fold별 + 전체), 일반 LSTM 대비 요약
  · 2절  시각화: 실제 vs 예측 시계열, 산점도 · 오차 분포, 시간대별 · 평일/주말별 성능
  · 3절  7월 peak 분석: 학습 범위(약 202kW)를 넘는 고온기 peak를 얼마나 따라가는가, 월별 peak 지표
  · 4절  오차 원인 구간별 MAE 개선율, 전력 급증(직전 대비 40%↑) 탐지 성능
  · 5절  결과 엑셀 저장
- 지표 읽는 법
  · 평균오차(+과소) : 실제 − 예측의 평균. 양수면 과소예측(실제가 더 큼) 경향
  · 허용 ±10% (%)   : 오차율 ±10% 이내(또는 절대오차 8kW 미만)인 시간의 비율
  · 과소 / 과대 (%) : 허용 범위를 벗어나면서 실제가 더 큰 / 예측이 더 큰 시간의 비율
  · 일 peak MAE     : 근무일(실제 일 최대 100kW 이상)의 하루 최대전력 오차
- 핵심 결과 (노트북에 저장된 실행 결과 기준)
  · 8:2 분할
      일반 LSTM   RMSE 13.437 / MAE 9.158 / R² 0.952 / 허용 72.5%
      보강 + 보정 RMSE  8.900 / MAE 6.166 / R² 0.979 / 허용 87.7%   (MAE -32.7%, RMSE -33.8%)
  · 확장 윈도우 (전체 3,084시간)
      일반 LSTM   RMSE 12.929 / MAE 8.765 / R² 0.951 / 허용 76.2%
      보강 + 보정 RMSE  9.666 / MAE 6.359 / R² 0.972 / 허용 86.3%   (MAE -27.5%, RMSE -25.2%)
  · 7월 근무일 일 최대전력 오차(MAE) 19.0kW → 8.7kW, 7월 R² 0.921 → 0.966
  · 급증 탐지(8:2 테스트) Recall 0.37 → 0.77, F1 0.49 → 0.69
  · 보강 LSTM 단독은 확장 윈도우에서 일반 LSTM보다 나쁘다 (MAE 11.62 vs 8.77). 보정 단계까지 거쳐야 개선된다.
  * 7번의 "MAE 8.74 → 6.34, RMSE 12.72 → 9.45"는 이전 실행 값이다. LSTM은 실행할 때마다
    소수점 아래가 조금씩 달라지며, 현재 노트북 저장 결과의 확장 윈도우 fold 평균은
    MAE 8.77 → 6.36, RMSE 12.75 → 9.50 이다.
- 실행 방법
  · 같은 폴더에 okm_augumented_2021_processed.xlsx 와 LSTM_AIModel_Enhanced.py 가 있어야 한다.
  · 필요 라이브러리: tensorflow, scikit-learn, pandas, numpy, matplotlib, openpyxl
  · 처음 실행(enhanced_results.pkl 없음): 검증 구간 5개 × LSTM 8개를 학습한다.
    CPU 기준 약 50분, GPU면 훨씬 빠르다. 학습 후 enhanced_results.pkl 로 저장한다.
  · 이후 실행: 저장된 결과를 불러와 표와 그래프만 만든다. 다시 학습하려면 설정 셀에서 RETRAIN = True.
- 출력
  · enhanced_results.pkl           학습 결과 캐시. 9번(Optimizing31_MILP)이 선택적으로 읽어
                                   가동 상태 전력 예측을 보강 + 보정 LSTM 예측으로 바꾼다.
  · 보강보정모델_성능리포트.xlsx   11개 시트 (요약, 8대2, 확장윈도우_fold별, 확장윈도우_전체,
                                   7월_peak지표, 7월_일peak, 월별_peak, 오차원인구간, 급증탐지,
                                   8대2_예측값, 확장윈도우_예측값)

9. Optimizing31_MILP.ipynb — Peak · 비용 최적화 및 인원 배치
--------------------------------------------------------------------------
- 월 · 2주 생산 목표를 지키면서 월 최대 전력 Peak를 낮추고, 인건비 + 전기요금을 최소화하는
  라인 가동 시간 · 시간별 생산량 · 일용직 근무 배치를 MILP(scipy HiGHS)로 구한다.
- 구성
  · 전력 예측(ML + 보강+보정 LSTM 연결) + 과소예측 방지용 시간대 × 달 차등 안전마진
  · 1인당 생산량 ML (보수적 하위 30% 분위)
  · 라인 · 생산 MILP ↔ 일별 정수 근무패턴 배치 반복 (LP 쌍대값으로 인건비 단가 갱신)
  · 일용직 근무 규칙: 2 · 3 · 4시간 단기 근무, 5시간 이상 30분 단위, 무급 휴게, 단기 근무자 비율 50% 미만
  · 월별 리포트 · 제약 검증 · 인건비 분해
  · 1~9월 인원 배치표, 하루 목표 생산량별 인원 배치, 하루 계획 도구(월 · 생산량 · 강수 입력)
- 출력: Optimizing31_MILP_결과.xlsx, 인원배치표_1-9월.xlsx, 하루목표별_인원배치.xlsx,
        일일_인원배치_*.xlsx / .png

10. Legacy_vs_MILP.ipynb — 이전 방식(v5 · v6)과 MILP 비교
--------------------------------------------------------------------------
- 역할: MILP로 바꾸기 전의 최적화 방식(원본 v6, v5 노트북)에 9번과 같은 제약조건을 그대로 주면
  어떻게 되는지 확인하고, 본 모델(MILP)과 같은 표에서 비교한다.
- 이전 방식
  · v6 (순차 탐색)  월별로 시간마다 생산량 후보(기존의 50 ~ 150%)를 만들고, XGBoost로 Peak · 전력량을
                    예측해 비용(전력비 + 생산 편차 + Peak 패널티)이 가장 낮은 후보를 고른다.
                    월 생산량은 라그랑주 승수를 이분 탐색해 기존 100%에 맞춘다. 인원은 기존값 고정.
  · v5 (인원 유동)  v6 구조 + AI 인원 배분(70 ~ 120%) + 일용직 근무패턴 LP + 폭염 시간대 생산 분산
- 비교하는 다섯 가지

- 해석
  · 같은 제약을 줘도 이전 방식은 라인을 끌 수 없고 인원이 고정이라 줄일 여지가 거의 없다.
    총비용 절감액은 MILP가 ③의 약 34배이다.
  · ③의 전력 절감(1.2%)은 XGBoost가 "생산을 줄이면 전력이 준다"고 반응한 결과이며, 실측 기준으로
    다시 계산하면(④) 사라진다. 가동 중에는 생산량이 전력에 거의 영향을 주지 않기 때문이다.
  · 인원이 고정된 계획이 요구하는 1인당 생산성은 시간대별 기존 95분위를 넘는 시간이 14.2%
    (기존은 5%), 최대 2.10배이다. 라인 종료는 0시간, 생산일 안에서 쉬는 573시간은 그대로 남는다.
  · 7월 저녁(18 ~ 23시) 생산 비중: 기존 25.1% → 이전 방식 33.3% (늘림) → MILP 14.9% (줄임)
  · ①②③은 XGBoost 예측 기준, ④⑤는 실측 환산 기준이다. 같은 기준끼리 ③↔④, ④↔⑤로 비교한다.
